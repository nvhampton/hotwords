What to observe (read me before testing)

The plot: We want to know if Chrome 139+'s on-device Web Speech API silences the start-of-listening "ding" on Android. If yes, we ship continuous streaming. If no, we either accept dings or move to server-side STT.

Steps:

  1. Tap Try on-device install() first. Check what the capability pills show.
  2. Tap Start continuous. Speak a few words, then stay silent for ~15 seconds.
  3. Watch the log — recognition will likely onend after silence, and the code will start() again. Note whether you hear a "ding" on each restart.
  4. Try repeating with on-device installed vs not. Report back: ding present? ding silenced? recognition stayed alive?

Capability pill meanings: install() = on-device install API exists. available = on-device model is downloaded and ready. cloud-only = only the legacy cloud path is available.
